# Internationalization

**Phase: prepare.** The decision, owner and scope live in `RULES.md` §
Internationalization. This file records the locale set and the reasoning, so
future contributors do not relitigate which languages.

## What "prepare" means here

The resolver is complete; the catalogs are not. Concretely, today:

- `--lang <code>` and `JPEGZ_LANG` are accepted and resolved, with full
  precedence: `--lang` > `JPEGZ_LANG` > `LC_ALL` > `LC_MESSAGES` > `LANG`,
  English as the floor.
- All 50 locales parse, including the awkward ones. Only English has strings.
- A recognized locale with no catalog **warns on stderr and renders English**.
  It does not fail. A silent fallback is how a missing catalog goes unnoticed
  indefinitely, so the warning is the deliverable, not a placeholder.
- An unsupported *explicit* request (`--lang klingon`, `JPEGZ_LANG=xx`) is
  named in the warning. An unparseable *system* locale is not — the user did
  not ask jpegz for anything, and warning there would fire on every machine
  whose `LANG` we happen not to translate, training people to ignore it.

Flipping to **enforce** — where a missing translation breaks the build — waits
until the CLI's string surface stops churning. At that point the strings move
into a typed no-default struct so an incomplete locale is a compile error, and
tests 2, 3, 4 and 6 from the i18n skill land alongside.

## The canonical 50

```
am  ar* az  bg  bn  bs  da  de  el  en
es  fa* fi  fil fr  ha  he* hi  hr  hu
id  ig  is  it  ja  km  ko  mk  nb  nl
pa  pl  ps* pt_br  ro  ru  sl  sq  sr  sv
sw  ta  th  tr  uk  ur* vi  yo  zh_hans  zh_hant
```

`*` marks the five RTL locales: `ar he fa ps ur`.

**Selection lens:** high-computer-penetration languages **plus** deliberately
under-served ones (Hausa, Amharic, Yoruba, Igbo, Filipino), on a "seed adoption
where English penetration is thin" rationale. This is **not** a
top-50-by-speakers list, and proposals to swap entries should argue against
that lens rather than against speaker counts.

## Parsing rules that are easy to get wrong

`src/i18n/locale.zig` takes the **longest match**, and its tests are a labeled
corpus rather than a handful of happy cases, because every failure mode here is
silent:

- `fil` (Filipino) shares its first two bytes with `fi` (Finnish). A parser
  that takes two characters, or splits on the separator and keeps the head,
  turns every Filipino user into a Finnish one while passing all 2-letter
  tests.
- `pt_br`, `zh_hans`, `zh_hant` are single units, not a code plus a
  discardable suffix.
- Truncation happens only at separator boundaries, which is what keeps `fil`
  from ever being considered as `fi`.
- Platform decorations are accepted: any case, `-` or `_`, and the POSIX
  `de_DE.UTF-8` / `fr_FR@euro` forms.
- `C` and `POSIX` are not locales. They mean "no localization", which is a
  legitimate answer rather than an unsupported request to complain about.

**Chinese region folding.** Bare `zh` and region-only forms carry no script
subtag and would otherwise match nothing. CLDR's likely-subtags rule reduces to
three Traditional regions:

| Input | Result |
|---|---|
| `zh`, `zh_CN`, `zh_SG`, `zh_MY` | `zh_hans` (Simplified — the default) |
| `zh_TW`, `zh_HK`, `zh_MO` | `zh_hant` (Traditional) |
| `zh_Hant`, `zh_Hant_HK` | `zh_hant` — explicit script always beats region |

## Where the boundary sits

Locale *decisions* are pure computation and live in the Zig core, exposed as
`jpegz_locale_resolve`. Locale *rendering* is the CLI's job. The core returns
typed codes; turning a `FindingCode` into a sentence in someone's language is
presentation.

That split is why the precedence rule is unit-tested against explicit inputs
instead of by mutating a process environment — global state shared with every
other test in the binary.

## When translations are actually produced

Not yet, and the order matters. Per the i18n skill: structural gates prove
structure, not meaning. A general model emits fluent-looking garbage for
low-resource languages that passes every completeness and placeholder check.
Before trusting automated output for a locale, probe it (translate, then
back-translate, and read the result), ground terminology in an oracle the model
did not produce, and keep maker separate from checker. Honest incompleteness
beats forced garbage — which is exactly why the prepare phase warns rather than
shipping placeholder strings.

## Not yet built

- Localized aliases for `--lang` and `--help` (`--sprache`, `--hilfe`), and the
  comptime alias-merge collision guard they require. Note the guard is
  mandatory, not optional: with 50 locales, collisions are real — a documented
  case had Indonesian `--hanya` ("only") clash with Hausa `--hanya` ("path").
- Bilingual errors (localized message plus the English original with a
  "search for:" hint). Nothing to pair yet with only English present.
- RTL bidi marks when composing those bilingual lines.
